Run

Flashes the square (and the optional photodiode corner) at fixed intervals using the same scheduler as the experiment, sends a timing_flash marker on every flash, then reports how closely the browser kept to the schedule. Use the same browser window size, display, and fullscreen state as a real session, with other tabs closed.

Measuring the real screen lag (hardware)

  1. Tape a photodiode (or a phone camera in slow motion) over the corner square; feed the diode into an EEG aux/trigger channel or a second LSL stream.
  2. Run this test with the bridge running and your recorder (LabRecorder) saving both the CorTextMarkers stream and the photodiode channel.
  3. Extract photodiode onsets (threshold crossing) to a CSV with an lsl_timestamp column, then run python tools/analyze_timing.py bridge/logs/markers_….csv --event timing_flash --photodiode pd_onsets.csv.
  4. The mean marker→light lag is the constant offset to subtract; its SD is the jitter you cannot remove. See TIMING_CHECKLIST.md for pass/fail thresholds.
